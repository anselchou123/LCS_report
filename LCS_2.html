網頁與演算法專家級：LCS 最長共同子序列互動報告

1. 什麼是 LCS？從「子序列」說起

在了解 LCS 之前，我們必須先知道什麼是「子序列」 (Subsequence)。

子序列指的是：從原本的字串中，隨意刪去某些字元（也可以不刪），但絕對不改變剩餘字元的相對順序所形成的新字串。換句話說，子序列在原字串中不需要是連續的。

那麼，最長共同子序列 (Longest Common Subsequence, LCS) 顧名思義，就是給定兩個字串，找出它們之間「長度最長」的那一個共同子序列。需要特別強調的是：LCS 的解答往往不只一個。只要兩組不同字元的組合，都能達到這個「最長」的長度，它們就都是正確的 LCS 解答！

2. 為什麼必須用動態規劃 (DP)？那些被記錄下來的歷史

如果我們要找兩個字串的 LCS，最直覺的想法是「暴力解」(Brute-Force)：

  • 暴力解的極限： 將字串 S1 的「所有可能子序列」列出來，再去字串 S2 裡面尋找。如果 S1 長度為 m，它的子序列就有 2^m 種組合。只要字串長度超過 30，演算法可能要算到天荒地老，時間複雜度高達 O(n · 2^m)。

這就是為什麼我們需要動態規劃 (DP)：利用「紀錄」來避開重複計算。

DP 的核心哲學是：「把算過的答案記錄下來」。
在 LCS 的 DP 解法中，我們建立了一個二維表格。表格裡的每一個格子 DP[i][j] 都在記錄著：「字串 S1 的前 i 個字元」與「字串 S2 的前 j 個字元」的 LCS 長度是多少？

當我們一步步往後計算時，我們根本不需要重新掃描前面的字串。因為前面的比對結果，早就化為數字安穩地躺在表格的左方、上方和左上方了！我們只要根據當前的字元相不相同，做個簡單的「查表」與「加法」，就能推導出新長度。這種「用空間（表格）換取時間」的策略，讓複雜度瞬間驟降到 O(m · n)。

為什麼表格要多一層保護？

建立 DP 表格時，我們會刻意在最前面多加第 0 行與第 0 列，並將它們填滿 0。這就是所謂的保護層 (Padding/Sentinel)。
因為在查表時，我們經常需要看「左上角」的值 (DP[i-1][j-1])。如果沒有這層 0，在比對第一個字元時程式就會發生陣列越界 (Index Out of Bounds)。這層 0 巧妙地代表了「空字串與任何字串的共同子序列長度為 0」，既保護了程式，也賦予了邊界合理的數學意義。

4. 回推找答案 (Backtracking) 的運作法則

填完表格，我們只知道 LCS 的「最長長度」在右下角，但不知道「字串是什麼」。這時我們需要從右下角開始，往左上角逆向回推 (Backtrack)。回推的法則非常明確：

原則 1：當比對字元「相同」時
這代表該字元絕對是 LCS 的一部分！我們將它記錄下來，並朝著對角線 左上方 (i-1, j-1) 移動，因為長度是從那裡加 1 過來的。

原則 2：當比對字元「不同」時
代表當前的長度是從之前繼承來的。我們去比較表格的 上方 (i-1, j) 與 左方 (i, j-1) 哪個數值比較大：
➔ 上方較大，往上走。
➔ 左方較大，往左走。
➔ 兩者一樣大： 這是最有趣的情況！代表往上走或往左走，都能湊出最長子序列。這就是為什麼 LCS 解答不只一個的根本原因！你可以走任意一邊，探索不同的路徑，得到不同的字串組合。

6. 核心程式碼解析 (C++)

這裡我們不放雜亂的樣板程式碼，直接鎖定 LCS 演算法的核心：1. 建立 DP 表格 與 2. 回推路徑。

第一部分：建表與查表紀錄

// 宣告時長度為 m+1 與 n+1，預設填入 0 (這就是我們說的保護層)
vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));

for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        if (s1[i - 1] == s2[j - 1]) {
            // 字元相同：直接取左上角的紀錄 + 1
            dp[i][j] = dp[i - 1][j - 1] + 1; 
        } else {
            // 字元不同：取左方與上方紀錄的最大值
            dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]); 
        }
    }
}

第二部分：回溯尋找答案

string lcs = "";
int i = m, j = n; // 從右下角開始

while (i > 0 && j > 0) {
    if (s1[i - 1] == s2[j - 1]) {
        // 情況 1：字元相同，將字元加入解答，往左上方移動
        lcs += s1[i - 1]; 
        i--; j--;
    } 
    else if (dp[i - 1][j] >= dp[i][j - 1]) {
        // 情況 2：上方紀錄 >= 左方紀錄，往上方移動 (相同時預設往上)
        i--; 
    } 
    else {
        // 情況 3：左方紀錄 > 上方紀錄，往左方移動
        j--; 
    }
}
// 最後因為是倒著找回來的，記得將字串反轉
reverse(lcs.begin(), lcs.end());

7. 總結

  • 本質精神：LCS 利用動態規劃，將龐大且不可能算完的指數級問題，化解為「紀錄」與「查表」的簡單動作。
  • 空間與保護：增加邊界 0 (保護層) 不僅省去程式碼處理邊界的麻煩，更確保了演算法邏輯的優雅。
  • 答案多樣性：我們從回溯邏輯中清楚看到，當相鄰格子數值相同時，不同的走法就造就了多樣化的 LCS 答案路徑。
